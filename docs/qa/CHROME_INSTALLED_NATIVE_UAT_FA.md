# SOKNA Bridge — آزمون Chrome + Native Host نصب‌شده

**محدوده این آزمون: فقط SOKNA Bridge مستقل.** هیچ وابستگی یا آزمون سامانه کافه وجود ندارد. اجرای Edge لازم نیست.

## روش آزمون مستقل

Workflow: `.github/workflows/bridge-chrome-native-installed.yml`

- روی Windows Runner موقت GitHub، Setup از commit دقیق PR ساخته و نصب می‌شود.
- فایل افزونه از همان محل نصب Inno در **Google Chrome for Testing** بارگذاری می‌شود. Chrome for Testing نسخه رسمی گوگل برای اتوماسیون است؛ از نسخه ۱۳۷ Chrome معمولی، قابلیت `--load-extension` در آن حذف شده ولی در Chrome for Testing وجود دارد.
- رجیستری Chrome Native Messaging باید توسط **خود نصب‌کننده** ساخته شده باشد؛ آزمون ابتدا این شرط را بررسی می‌کند.
- در بافت واقعی افزونه داخل Chrome، شناسه و نسخه بررسی می‌شوند؛ مجوز `nativeMessaging` و عدم اعطای ضمنی مجوز دامنه اختیاری نیز بررسی می‌شوند.
- درخواست `host.ping` باید از داخل Chrome به Host نصب‌شده برسد و پاسخ `host.pong` با شناسه همسان بدهد.
- پیام ناشناخته و شناسه فرمان نامعتبر باید با `ok:false` رد شوند.
- رجیستری Host فقط در Runner موقت حذف می‌شود؛ درخواست بعدی نباید موفق جلوه کند؛ رجیستری بازسازی شده و پیام بعدی باید پاسخ صحیح بدهد.
- گزارش JSON صرفاً شامل نسخه‌ها، شناسه افزونه و نشانگرهای آزمون است، نه token یا داده شخصی. در صورت PASS، به‌صورت artifact محدود ۱۴روزه ذخیره می‌شود.

## مرز اعتبار

موفقیت این workflow به معنی تأیید مسیر **Chrome for Testing + افزونه بارگذاری‌شده + Native Host نصب‌شده** است، نه به معنی گذر از تمام آزمون‌های عملیاتی. این موارد مستقل باقی می‌مانند: نصب دستی افزونه از `chrome://extensions` در Chrome معمولی، سناریوهای ۷۵گانه، ارتقا از نسخه قدیمی، بازیابی در قطع ناگهانی واقعی، ممیزی حریم خصوصی و تأیید صریح مالک برای انتشار.

**هیچ Merge، Tag، Release یا Deployment خودکاری مجاز نیست.**
