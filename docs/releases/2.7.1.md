# SOKNA Bridge 2.7.1

SOKNA Bridge 2.7.1 is a transport-correctness and diagnosability release driven by live connected-chat testing after 2.7.0.

## P0 — no silent semantic command loss
- Semantic scanning is now **assistant-message scoped** instead of parsing `document.body.innerText`.
- START/END markers are paired only inside the same completed assistant message candidate.
- User messages, handshake documentation and non-standalone examples are non-executable.
- A message identity + raw hash attempt identity prevents same-node re-dispatch without hiding an exact duplicate sent as a new assistant message.
- `RECONCILE` now scans and recovers new commands instead of seeding them into a silent `seen` set.
- runtime messaging failures are persisted in extension local diagnostics instead of `.catch(()=>{})`.
- The connection handshake no longer contains a raw executable SOKNA marker.

## Duplicate semantics
- Exact duplicates are no longer silent.
- Background returns a correlated duplicate STATUS containing the original command id, state and result reference.
- Every new accepted command queues an explicit accepted STATUS before execution.

## Persistent transport observability
Extension trace events now include:
- `semantic.detected`
- `semantic.rejected`
- `semantic.dispatch_started`
- `semantic.dispatch_failed`
- `background.received`
- `agent.forward_started`
- `agent.accepted`
- `result.received`
- `chat.delivery_started`
- `chat.delivery_completed`
- `chat.delivery_failed`

Fallback semantic/content diagnostics survive service-worker/runtime-message failures in `chrome.storage.local`.

## Connected state verification
- `armed` is no longer equivalent to green/healthy.
- Connect/Re-arm performs a lightweight semantic → background → Agent probe and separately checks session + delivery readiness.
- Full green is reserved for **Connected — End-to-End Verified**.
- Degraded states distinguish Transport Unverified, Agent Unreachable, Delivery Unavailable and Needs Re-arm.
- Child-frame teardown/re-arm failures are diagnostic warnings; only top-frame re-arm failures degrade the whole tab.

## Full diagnostics
New extension-local action:
- `bridge.diagnostics.get`

Bootstrap exposes:
- `agent_actions`
- `extension_actions`
- `effective_actions`

Popup Advanced Diagnostics adds:
- Refresh Full Diagnostics
- Copy Full Diagnostics
- Download Diagnostics.json
- Send Diagnostics to this Chat
- Create Support Bundle
- Open Logs

AI-pulled diagnostics are bounded; popup export can include the fuller local snapshot.

## Support Bundle resilience
- Fixed the JsonNode redaction crash that could produce **The node already has a parent**.
- Bundle collection is now per-file best effort.
- Malformed JSON, locked logs, invalid text or inaccessible individual files no longer abort the entire bundle.
- `bundle-errors.json` records skipped failures.
- `bundle-manifest.json` reports `partial`, error count and files written.
- Support-bundle failure guidance no longer tells the user to inspect the bundle that failed.

## Control Center
- RTL-first Tahoma-based layout and clearer information hierarchy.
- Separate Agent Health, Primary Actions and Maintenance sections.
- Structured operation-error panel instead of dumping raw JSON into the Status page.
- Copy details, open logs, retry and minimal diagnostics actions.
- Dedicated Diagnostics tab with refresh/copy/save/support controls.
- Workspace inspect action and clearer onboarding steps.
- Control Center self-test now verifies Maintenance is installed.

## Instagram research and approval
- Explicit adapter readiness with login/challenge/DOM-not-ready states.
- New human-in-the-loop actions:
  - `instagram.adapter.status`
  - `instagram.research.plan`
  - `instagram.candidates.get`
  - `instagram.candidates.attach`
  - `instagram.selection.confirm`
  - `instagram.selection.reject`
  - `instagram.export`
- Research plans produce bounded candidate sets.
- Visual candidate batches can be attached to the connected Chat for observable-content review.
- Identity-sensitive selection requires user approval; export cannot bypass approval.
- The system does not identify a real person from face imagery alone.

## Regression coverage
Adds a semantic runtime mock gate covering:
- user message marker must not dispatch
- assistant unique command dispatches once
- exact duplicate reaches background for explicit duplicate handling
- RECONCILE race recovers the command
- unmatched marker in an earlier message cannot corrupt a later command
- historical baseline command does not execute
- runtime send rejection persists a diagnostic
- non-standalone documentation does not execute

Windows P1 acceptance also injects malformed state + a locked log and requires a successful partial Support Bundle.

## Live acceptance
After installation, transport validation must be performed in a completely new Chat:
1. Connect this Chat
2. require End-to-End Verified
3. send unique ping
4. bootstrap
5. agent.capabilities
6. workspace.list
7. repo.inspect
8. Instagram scan

No exact executable Bridge marker should be placed in explanatory prose during the test.
