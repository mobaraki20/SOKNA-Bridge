# SOKNA Bridge 2.7.1-r2

Semantic message-intake reliability hotfix for Connected Chat.

## What changed

- Extension version: 3.12.2
- Semantic runtime: 2.1.0
- Agent runtime remains 2.7.1
- Adds per-connection intake challenge/proof before Connected Chat is considered end-to-end verified.
- Adds marker-first discovery for Chat frontends that do not expose the legacy assistant/turn selectors.
- Requires the active per-connection `bridge_nonce` before connected semantic commands can dispatch.
- Keeps message intake fail-closed: missing proof, stale/wrong nonce, editable/user-role markers, and historical markers are not executed.
- Keeps stable DOM-node identity so historical commands do not become new commands when the conversation DOM grows.
- Retains `Connected — Message Intake Unverified` instead of false-green health when intake is not proven.
