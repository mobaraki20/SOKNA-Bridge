# SOKNA Bridge 2.7.1-r9

Reliability-kernel refactor following the r8 architecture/reliability audit.

## Scope

r9 preserves Agent 2.7.1 and the established Workspace, Artifact, Permission and Job cores. The changes are concentrated in the ChatGPT Adapter, command terminal outcomes, durable browser state, delivery acknowledgement, origin registration and bootstrap/resume orchestration.

## Reliability fixes

### Universal terminal rejection / visible NACK

A correlated command rejected by the session/preflight gate now has one explicit terminal outcome with:
- `executed=false`;
- machine-readable error code;
- retryability;
- recovery action;
- durable terminal event/NACK delivery.

A gate rejection can no longer disappear as a silent diagnostic-only event.

### Semantic outcome correctness

Semantic dispatch now distinguishes `semantic.dispatched`, `semantic.rejected` and `semantic.dispatch_failed`. A rejected command is never counted as dispatched.

### Execution state separated from delivery state

Execution and delivery use independent state. An ACK/failure for an older RESULT cannot overwrite or clear a newer running command.

Command idempotency is scoped to conversation + command id while preserving the original wire command id in STATUS/RESULT envelopes.

### Delivery ACK v3

Positive delivery acknowledgement requires an authoritative user-message shell. `document.body` fallback is diagnostic-only and can never positively ACK a result.

Large/virtualized RESULTs can be correlated by envelope type + id/eventId even when the visible DOM contains only the leading portion of the payload. STATUS and RESULT remain type-separated, and a payload still present in the composer never counts as delivered.

### Multi-origin ChatGPT Adapter

Built-in origins remain compatible:
- `https://chatgpt.com`
- `https://gpt.arzanai.com`

Additional ChatGPT-compatible HTTPS origins are fail-closed by default and require an explicit user permission action in the Popup. The extension registers the Adapter only for the approved origin; it does not auto-enable unknown domains or use `<all_urls>`.

### Durable bootstrap / resume

The browser-side bootstrap gate is persisted in `chrome.storage.session` instead of an in-memory Set, so service-worker restart does not silently lose authority for the current browser session.

Conversation identity supports a controlled provisional URL -> concrete `/c/<id>` migration while preventing cross-conversation reuse.

`bridge.bootstrap` is augmented with machine-readable extension policy for protocol limits, idempotency, terminal outcomes, delivery ACK, artifact routing, recovery actions, approved origins and deterministic next action.

## Release gate

Publication is allowed only after the exact candidate passes:
- Reliability Kernel Validation;
- Native Agent CI;
- full Windows Agent Validation / exact-RC evidence;
- Live Connected Chat UAT for browser-only acceptance cases.

The r8 tag remains immutable and is not moved.
