# SOKNA Bridge 2.7.1-r3

Clean evidence/release follow-up for the Connected Chat semantic intake hotfix.

## What is carried forward

- Extension version: 3.12.2
- Semantic runtime: 2.1.0
- Agent runtime: 2.7.1
- Per-connection intake challenge/proof before Connected Chat is considered end-to-end verified.
- Marker-first discovery for Chat frontends that do not expose the legacy assistant/turn selectors.
- Active per-connection `bridge_nonce` required before connected semantic commands can dispatch.
- Fail-closed handling for missing proof, stale/wrong nonce, editable/user-role markers, and historical markers.
- Stable DOM-node identity so historical commands do not become new commands when the conversation DOM grows.
- `Connected — Message Intake Unverified` remains visible until intake is actually proven.

## r3 correction

The r2 functional build passed its Windows and semantic validation, but its exact-RC evidence file reported a stale `candidate_agent_version=2.6.0` because the evidence writer read a hard-coded v2.6.0 capabilities path.

r3 fixes the evidence path/version source of truth:

- derives `candidate_agent_version` from the exact source manifest;
- loads the matching `native/runtime/v<version>/AGENT_CAPABILITIES.json`;
- requires that capabilities version to match the source manifest;
- cross-checks the extension version;
- release CI explicitly verifies evidence agent version, extension version, and exact source commit.

## Release safety

- Pull requests targeting `release/2.7.1` run the full Windows validation profile before merge.
- Publication remains gated to pushes on `release/2.7.1` after validation succeeds.
- The immutable release tag is `sokna-agent-2.7.1-r3`.
- A preflight checks the r3 tag before the expensive release validation/publish path.
