# SOKNA Bridge 2.7.1-r10

Reliability Architecture candidate.

## Versions

- Agent runtime: `2.7.1`
- Extension: `3.13.0`
- Semantic adapter: `2.1.1`
- Candidate ref: `sokna-agent-2.7.1-r10`

## Product invariant

Bridge is attached to the ChatGPT interface, not to one fixed ChatGPT URL. Approved HTTPS ChatGPT origins and route shapes are adapter concerns; durable command, artifact, job and session state live below the page adapter.

## Architecture changes

- Native Broker command ledger is authoritative for Agent-owned and Extension-owned actions.
- Conversation-scoped command IDs have durable accepted/running/terminal states and replay.
- Interrupted mutating commands fail closed as `outcome_unknown`; they are not blindly re-executed.
- `bridge.command.get/list` provide one recovery namespace.
- MCP-shaped Tool descriptors use JSON Schema 2020-12 and risk/idempotency annotations.
- Candidate qualification requires zero effective actions without a machine-readable contract.
- Chat presentation ACK is telemetry, not execution truth.
- Old `delivery_uncertain` records migrate to terminal `presentation_expired` history and cannot poison current Bridge health.

## Browser

The primary Browser interface is no longer the custom recipe format.

Interactive tools:
- `browser.tabs.list`
- `browser.tab.open`
- `browser.tab.claim`
- `browser.tab.release`
- `browser.page.snapshot`
- `browser.page.text`
- `browser.page.click`
- `browser.page.fill`
- `browser.page.scroll`
- `browser.page.wait`
- `browser.page.screenshot`

The Browser page engine adapts stable-ref/snapshot/action patterns from `whg517/browser-bridge v0.7.1` (Apache-2.0) while keeping SOKNA transport, policy, Artifact and recovery boundaries.

Browser security:
- Browser target origin approval is separate from ChatGPT-origin approval.
- HTTP/HTTPS Browser origins require explicit user permission from the Extension popup.
- Every Chat claims one exact tab; actions target that tab ID directly.
- Origin navigation invalidates the claim fail-closed.
- No public eval/cookie/storage primitives.
- Screenshot uses Chrome Debugger/CDP on the exact claimed tab and returns a durable `artifact_ref`.
- The old Browser recipe/audit runner remains only for QA/compatibility.

## Credentials

- Windows DPAPI current-user storage remains the credential backend.
- Credential create/update/delete is local-only in Control Center.
- AI can list opaque credential refs and usernames, never secret values.
- Browser fill may use `credential_ref + credential_field`; secret resolution occurs across the trusted Native Host boundary and is cleared after the page dispatch.
- Secret values are not written to command ledger, diagnostics or RESULT.

## Artifacts

- Extension-created files can be ingested into ArtifactRoot through a bounded native ingress.
- MIME, extension and actual payload signatures are verified before publication.
- Outbound Chat attachment defers while the Assistant is generating instead of destroying the transfer.

## Workspaces, permissions, components and automation

Existing policy engines are retained after build-vs-adopt review:
- workspace path/grant/tool intersection and reparse protections;
- explicit executable allowlists for `process.run`;
- Artifact Provider verification before component activation;
- process/service ownership checks;
- LKG rollback;
- automation job-bound grants and concurrency/dedupe.

All exposed actions now have MCP-style contracts.

## Local operations

- Control Center adds local Credential management.
- `bridge.doctor` checks Agent capabilities, Broker ledger, ArtifactRoot, workspace registry, Browser QA, credential refs and Tool Registry coverage.
- Session open/resume/checkpoint/close is routed through the durable Native Broker.

## Qualification

r10 is not released merely because source CI passes.

The final candidate must pass one exact-commit Windows qualification that builds the installer and runs the full clean-install/repair/upgrade/rollback/uninstall acceptance. Then a fresh-Chat black-box UAT must pass without repository/source access:

1. connect on the active ChatGPT URL;
2. `bridge.doctor` passes and reports zero uncontracted actions;
3. approve `http://127.0.0.1:18080` as a Browser origin;
4. discover and claim/open the SoknaCafe tab;
5. snapshot and capture the login page;
6. fill login using `sokna-local-admin` by credential ref;
7. login and capture the dashboard;
8. attach both screenshot artifacts into Chat;
9. refresh Chat and recover command/results without re-execution.

Only after that UAT should the immutable r10 release be promoted.
