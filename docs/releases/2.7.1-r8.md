# SOKNA Bridge 2.7.1-r8

Operator recovery and authoritative Popup state follow-up for r7.

## What r7 already fixed and r8 preserves

- submitted RESULTs do not auto-resend while awaiting visibility acknowledgement;
- ACK polling is bounded and ends in `delivery_uncertain` rather than an infinite resend loop;
- semantic intake proof survives reload/re-arm for the same conversation/challenge;
- active nonce enforcement remains fail-closed;
- user-draft protection remains unchanged;
- STATUS-vs-RESULT visibility matching remains envelope-type aware;
- duplicate command IDs remain idempotent.

## r8 fixes

### Delivery uncertain recovery UI

When a submitted RESULT reaches `delivery_uncertain`, the Popup now shows a dedicated recovery card with the exact record ID and a **Re-check delivery** action.

That action is visibility-only:
- targets only an existing `delivery_uncertain` record;
- calls the forced ACK-poll path;
- executes `CHECK_RESULT_VISIBLE`;
- never calls `POST_RESULT`;
- never blindly marks a result delivered;
- if visibility is confirmed, the record becomes acknowledged and the connection returns to Ready;
- if visibility is still not confirmed, the record remains `delivery_uncertain` and Needs Action.

### Authoritative status precedence

Popup green state now comes from final authoritative `status.transportVerified`, not raw probe health.

`Needs Action` / `actionRequired=true` always overrides probe-green state.

The STATUS health projection now also exposes `transportVerified` from the final status, eliminating the previous contradiction where:
- probe/health could be true,
- final status could be Needs Action / false,
- Popup could still render End-to-End Verified.

### Dynamic extension version

The Popup version label is now read from `chrome.runtime.getManifest().version` instead of a stale hard-coded string.

## Regression coverage

New UI/state regressions verify:
- delivery_uncertain exposes recovery UI;
- manual recovery is visibility-only and explicitly non-resubmitting;
- failed manual re-check remains delivery_uncertain and non-sendable;
- successful visibility acknowledgement becomes acknowledged;
- Needs Action overrides probe/health green;
- status.transportVerified=false cannot render End-to-End Verified;
- Popup version comes from the runtime manifest;
- all r7 transport/semantic safety regressions remain in the full suite.
