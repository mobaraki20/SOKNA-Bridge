# SOKNA Bridge 2.7.1-r5

Installer recovery hotfix for a live SOKNA runtime that still owns the configured agent endpoint but is unhealthy and returns HTTP 500.

## Live failure fixed

The user's r4 support bundle proved this exact state:

- install root exists at a normal per-user path such as `%LOCALAPPDATA%\Programs\SOKNA Agent`;
- `config.json` exists;
- runtime ownership state is missing;
- the configured agent port is still occupied (8766 in the live incident);
- the endpoint responds HTTP 500;
- r4 required a healthy semantic identity probe before process recovery, so it skipped recovery and `initialize` failed with `AGENT_ENDPOINT_UNAVAILABLE_AFTER_PREP`.

## r5 behavior

- A healthy endpoint is no longer required before attempting recovery.
- Recovery proves the old runtime by:
  - exact trusted `agent.ps1` path;
  - exact trusted `ConfigPath`;
  - matching configured port and token;
  - unique main PowerShell/pwsh agent process.
- Scheduler, job-worker, and startup-probe processes remain excluded.
- Unknown or ambiguous processes remain fail-closed and are never killed.
- If a healthy authenticated SOKNA endpoint exists but no trusted process matches it, installation still fails closed.
- The proven unhealthy runtime is stopped, the endpoint is released, configuration is preserved, and initialization continues.

## Live-shaped regression coverage

Full Windows acceptance now reproduces the user incident with:

- install path containing a space: `...\SOKNA Agent`;
- exact port `8766`;
- missing ownership state;
- a running `agent.ps1` launched with the exact `ConfigPath`;
- an endpoint deliberately returning HTTP 500.

Acceptance requires:

- the exact injected process to exit;
- `recovered_untracked_runtime_stopped=true`;
- recovery PID to match the injected process;
- recovery port to equal 8766;
- recovery source to be `current-config`;
- the new 2.7.1 runtime to pass health;
- legacy-untracked recovery, active reinstall, repair, upgrade, rollback, support-bundle, and uninstall acceptance to remain green.
